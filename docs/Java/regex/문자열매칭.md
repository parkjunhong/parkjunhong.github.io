# 질문: '@NotEmpty String' 찾기.
```
eclipse  > Search 에서 정규식으로 ....

"@NotEmpty String" 찾기.

- "@NotEmpty String[]" : 제외
- "@NotEmpty String []": 제외
- "@NotEmpty String ...": 제외
- "@NotEmpty String...": 제외
```

# 답변

사용하려는 정규식은 다음입니다.

```regex
@NotEmpty\s+String\b(?!\s*(?:\[\]|\.\.\.))(?=\s+\w)
```

전체 목적은 **`@NotEmpty String 변수명` 형태만 찾고**, 아래 형태는 제외하는 것입니다.

```java
@NotEmpty String[] names
@NotEmpty String [] names
@NotEmpty String... names
@NotEmpty String ... names
```

## 전체 구조

```regex
@NotEmpty
\s+
String
\b
(?!\s*(?:\[\]|\.\.\.))
(?=\s+\w)
```

각 부분을 순서대로 보면 됩니다.

---

## 1. `@NotEmpty`

```regex
@NotEmpty
```

문자 그대로 `@NotEmpty`를 찾습니다.

매칭 예:

```java
@NotEmpty String name
```

여기서 `@`는 대부분의 정규식 엔진에서 특별한 의미가 없으므로 그대로 써도 됩니다.

---

## 2. `\s+`

```regex
\s+
```

`@NotEmpty` 뒤의 공백을 의미합니다.

`\s`는 공백류 문자를 뜻합니다.

대표적으로 다음을 포함합니다.

```text
스페이스
탭
줄바꿈
캐리지 리턴
```

`+`는 **1개 이상 반복**입니다.

즉 아래는 모두 매칭됩니다.

```java
@NotEmpty String name
@NotEmpty    String name
@NotEmpty	String name
```

하지만 아래처럼 공백이 없으면 매칭되지 않습니다.

```java
@NotEmptyString name
```

---

## 3. `String`

```regex
String
```

문자 그대로 `String`을 찾습니다.

```java
@NotEmpty String name
```

여기까지는 `@NotEmpty` + 공백 + `String`을 찾는 부분입니다.

---

## 4. `\b`

```regex
\b
```

`\b`는 **단어 경계**, 즉 word boundary입니다.

여기서는 `String`이라는 단어가 다른 단어의 일부로 잡히는 것을 막습니다.

예를 들어 `\b`가 없으면 이론적으로 아래 같은 코드에서 `String` 부분만 매칭될 수 있습니다.

```java
@NotEmpty StringBuilder sb
```

하지만 `String\b`를 사용하면 `String` 바로 뒤가 단어 문자이면 매칭되지 않습니다.

정규식에서 보통 단어 문자는 다음입니다.

```text
A-Z
a-z
0-9
_
```

그래서 다음은 매칭되지 않습니다.

```java
@NotEmpty StringBuilder sb
@NotEmpty String_value
@NotEmpty String1 value
```

반면 다음은 `String` 뒤에 공백, `[`, `.` 등이 오므로 일단 `\b` 조건은 통과할 수 있습니다.

```java
@NotEmpty String name
@NotEmpty String[] names
@NotEmpty String... names
```

단, 배열과 가변인자는 뒤쪽의 제외 조건에서 걸러집니다.

---

## 5. `(?!\s*(?:\[\]|\.\.\.))`

```regex
(?!\s*(?:\[\]|\.\.\.))
```

이 부분이 핵심 제외 조건입니다.

이것은 **부정형 전방탐색**, negative lookahead입니다.

뜻은 다음과 같습니다.

> 현재 위치, 즉 `String` 바로 뒤에서 봤을 때
> 공백이 0개 이상 나온 뒤 `[]` 또는 `...`가 오면 매칭하지 말라.

### 5-1. `(?! ... )`

```regex
(?!패턴)
```

`(?!...)`는 **뒤에 이 패턴이 오면 실패**하라는 뜻입니다.

예를 들어:

```regex
String(?!Builder)
```

이 정규식은 `String` 뒤에 `Builder`가 오면 매칭하지 않습니다.

```java
String name        // 매칭
StringBuilder sb   // 제외
```

현재 정규식에서는 `String` 뒤에 배열 표시나 가변인자 표시가 오면 제외하려고 사용합니다.

---

### 5-2. `\s*`

```regex
\s*
```

공백이 0개 이상 있다는 뜻입니다.

`*`는 **0개 이상 반복**입니다.

이것 때문에 아래 두 경우를 모두 처리할 수 있습니다.

```java
String[]    // 공백 0개
String []   // 공백 1개
String    [] // 공백 여러 개
```

그리고 가변인자도 마찬가지입니다.

```java
String...    // 공백 0개
String ...   // 공백 1개
String    ... // 공백 여러 개
```

---

### 5-3. `(?: ... )`

```regex
(?:\[\]|\.\.\.)
```

`(?:...)`는 **비캡처 그룹**입니다.

일반 괄호 `( ... )`는 그룹을 만들고, 필요하면 나중에 `$1`, `$2` 같은 식으로 참조할 수 있습니다.

하지만 여기서는 그룹을 나중에 참조할 필요가 없습니다. 단지 `|` 조건을 묶기 위해 괄호가 필요한 것입니다.

그래서 캡처하지 않는 그룹인 `(?:...)`를 사용합니다.

즉 의미는 일반 그룹과 거의 같지만, 결과 그룹으로 저장하지 않습니다.

---

### 5-4. `\[\]`

```regex
\[\]
```

문자 그대로 `[]`를 찾습니다.

정규식에서 `[`와 `]`는 문자 클래스를 만들 때 쓰는 특수문자입니다.

예:

```regex
[abc]
```

이것은 `a`, `b`, `c` 중 하나를 뜻합니다.

따라서 진짜 대괄호 문자를 찾으려면 이스케이프해야 합니다.

```regex
\[
\]
```

그래서 `[]` 리터럴은 다음처럼 씁니다.

```regex
\[\]
```

---

### 5-5. `|`

```regex
\[\]|\.\.\.
```

`|`는 OR입니다.

즉 다음 둘 중 하나입니다.

```regex
\[\]
```

또는

```regex
\.\.\.
```

---

### 5-6. `\.\.\.`

```regex
\.\.\.
```

문자 그대로 `...`를 찾습니다.

정규식에서 `.`은 아무 문자 하나를 뜻하는 특수문자입니다.

예:

```regex
a.b
```

이것은 아래 모두에 매칭될 수 있습니다.

```text
aab
acb
a-b
```

그래서 진짜 점 문자 `.`을 찾으려면 `\.`처럼 이스케이프해야 합니다.

점 3개 `...`를 문자 그대로 찾으려면:

```regex
\.\.\.
```

---

## 6. `(?=\s+\w)`

```regex
(?=\s+\w)
```

이 부분은 **긍정형 전방탐색**, positive lookahead입니다.

뜻은 다음과 같습니다.

> 현재 위치에서 봤을 때, 공백 1개 이상 뒤에 단어 문자가 와야 한다.

즉 `String` 뒤에 변수명 같은 것이 있어야 매칭되도록 제한합니다.

### 6-1. `(?= ... )`

```regex
(?=패턴)
```

`(?=...)`는 **뒤에 이 패턴이 와야 성공**한다는 뜻입니다.

다만 실제로 그 부분을 소비하지는 않습니다.

예:

```regex
String(?=\s+\w)
```

이 정규식은 `String` 뒤에 공백 + 단어 문자가 있어야 `String`을 매칭합니다.

```java
String name     // 매칭
String          // 제외
String[] names  // 제외 가능
String... args  // 제외 가능
```

---

### 6-2. `\s+\w`

```regex
\s+\w
```

공백 1개 이상 뒤에 단어 문자가 오는지 확인합니다.

`\w`는 보통 다음을 뜻합니다.

```text
A-Z
a-z
0-9
_
```

즉 아래처럼 변수명이 바로 이어지는 경우를 기대합니다.

```java
@NotEmpty String name
@NotEmpty String value
@NotEmpty String _value
@NotEmpty String name1
```

---

## 왜 `(?!...)`와 `(?=...)`가 둘 다 필요한가?

현재 정규식은 두 가지 조건을 동시에 만족해야 합니다.

```regex
(?!\s*(?:\[\]|\.\.\.))
```

이 조건은 **배열과 가변인자를 제외**합니다.

```java
@NotEmpty String[] names    // 제외
@NotEmpty String [] names   // 제외
@NotEmpty String... args    // 제외
@NotEmpty String ... args   // 제외
```

그리고:

```regex
(?=\s+\w)
```

이 조건은 **String 뒤에 변수명처럼 보이는 것이 있어야 한다**고 제한합니다.

```java
@NotEmpty String name       // 매칭
@NotEmpty String value      // 매칭
```

둘을 함께 쓰면:

```regex
String\b(?!\s*(?:\[\]|\.\.\.))(?=\s+\w)
```

의미는 다음과 같습니다.

> `String`이라는 정확한 단어를 찾되,
> 바로 뒤에 공백 후 `[]`나 `...`가 오면 제외하고,
> 공백 후 변수명으로 보이는 단어 문자가 오는 경우만 허용한다.

---

## 예시별 매칭 여부

| 코드                           | 결과 | 이유                              |
| ---------------------------- | -: | ------------------------------- |
| `@NotEmpty String name`      | 매칭 | `String` 뒤에 공백 + 변수명            |
| `@NotEmpty   String name`    | 매칭 | `\s+`가 여러 공백 허용                 |
| `@NotEmpty String_name`      | 제외 | `String\b`에서 실패, `_`는 단어 문자     |
| `@NotEmpty StringBuilder sb` | 제외 | `String\b`에서 실패                 |
| `@NotEmpty String[] names`   | 제외 | `(?!\s*\[\])`에서 실패              |
| `@NotEmpty String [] names`  | 제외 | 공백 후 `[]`라서 실패                  |
| `@NotEmpty String... names`  | 제외 | `(?!\s*\.\.\.)`에서 실패            |
| `@NotEmpty String ... names` | 제외 | 공백 후 `...`라서 실패                 |
| `@NotEmpty String`           | 제외 | 뒤에 공백 + 변수명이 없어서 `(?=\s+\w)` 실패 |
| `@NotEmpty String;`          | 제외 | 뒤에 공백 + 변수명이 없어서 실패             |

---

## 실제 매칭되는 범위

이 정규식은 전체 변수 선언문을 다 잡는 게 아니라, 기본적으로 아래 부분까지만 매칭합니다.

```java
@NotEmpty String name
```

위 코드에서 실제 매칭되는 텍스트는 보통 다음 부분입니다.

```java
@NotEmpty String
```

왜냐하면 마지막의 `(?=\s+\w)`는 **검사만 하고 소비하지 않는 전방탐색**이기 때문입니다.

즉 `name`은 매칭 결과에 포함되지 않습니다.

변수명까지 포함해서 찾고 싶다면 아래처럼 바꿀 수 있습니다.

```regex
@NotEmpty\s+String\b(?!\s*(?:\[\]|\.\.\.))\s+\w+
```

그러면 아래 전체가 매칭됩니다.

```java
@NotEmpty String name
```

## Eclipse Search에서 주의할 점

Eclipse의 Search에서 정규식을 사용할 때는 보통 Java 정규식 기반으로 동작합니다.

따라서 아래 문법은 사용 가능합니다.

```regex
\s
\b
(?:...)
(?!...)
(?=...)
```

다만 Java 코드 문자열 안에 넣는 것이 아니라 **Eclipse 검색창에 직접 입력하는 것**이라면 백슬래시를 두 번 쓸 필요는 없습니다.

검색창에는 그대로:

```regex
@NotEmpty\s+String\b(?!\s*(?:\[\]|\.\.\.))(?=\s+\w)
```

Java 문자열로 작성할 때는 백슬래시를 한 번 더 이스케이프해야 합니다.

```java
"@NotEmpty\\s+String\\b(?!\\s*(?:\\[\\]|\\.\\.\\.))(?=\\s+\\w)"
```

---

## 최종적으로 이 정규식은 적절한가?

네. 지금 목적에는 적절합니다.

```regex
@NotEmpty\s+String\b(?!\s*(?:\[\]|\.\.\.))(?=\s+\w)
```

다만 변수명이 한글이거나 `$`로 시작하는 경우까지 고려해야 하면 `\w`가 부족할 수 있습니다.

예를 들어 Java 변수명에는 `$`도 가능합니다.

```java
@NotEmpty String $name
```

이것까지 허용하려면 마지막을 이렇게 바꿀 수 있습니다.

```regex
@NotEmpty\s+String\b(?!\s*(?:\[\]|\.\.\.))(?=\s+[$\w])
```

일반적인 Java 코드 검색 목적이라면 처음 정규식 그대로 사용해도 충분합니다.
